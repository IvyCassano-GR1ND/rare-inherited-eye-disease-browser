# 眼科罕见病分类浏览器

中英对照的 Orphanet 眼科分类目录，支持树状展开、疾病定义、CSV 文献资料导入、症状与辅助检查关键词检索。纯静态 HTML/CSS/JavaScript，无后端、账号、密钥、数据库或第三方运行时依赖。

## 直接打开

双击根目录 `index.html` 即可离线使用，引用来源链接需联网。旧文件 `index..html` 已修正为 `index.html`。

当前包含 1,339 个去重条目、1,646 条分类路径；分类组、疾病实体和亚型分别标识，亚型默认隐藏。编号搜索为精确匹配；文字搜索支持中英文、中文别名，多个关键词用空格分隔（同时匹配）。临床检索仅匹配已导入记录的症状和辅助检查，不将定义原文当作已提取的临床证据，也不计算诊断概率。

## Cloudflare Pages 发布（推荐连接 GitHub）

在 Cloudflare **Workers & Pages** 中创建 **Pages** 项目，连接本 GitHub 仓库，使用以下配置：

| 设置 | 值 |
|---|---|
| 生产分支 | `main` |
| 框架预设 | `None` |
| 构建命令 | `npm run build` |
| 构建输出目录 | `dist` |
| 根目录 | 仓库根目录，留空 |
| 环境变量 | 无需密钥；如需指定 Node 版本，可设 `NODE_VERSION=22` |

构建仅使用 Node.js 内置模块，不需要安装项目依赖。`dist` 包含 `index.html`、`_headers` 和 `_redirects`，可直接发布。不要选择需要入口脚本的 Worker 项目。

也可在本地执行 `npm run build`，将 **dist 文件夹中的内容**（或包含这些文件的 ZIP，ZIP 顶层须为 index.html）上传至 Pages 的 Direct Upload。已有发布包可直接拖入，无需先构建。Direct Upload 与 Git 集成的项目模式不能直接切换；打算长期通过 GitHub 更新时，从一开始选 Git 集成。

官方说明：[静态 HTML 部署](https://developers.cloudflare.com/pages/framework-guides/deploy-anything/) · [直接上传](https://developers.cloudflare.com/pages/get-started/direct-upload/)

## 你和学妹如何补充资料

1. 打开网页，选择**具体疾病或亚型**，点击“下载此疾病填写模板”。也可使用 `templates/clinical-template.csv` 空模板，一次填写多个疾病。
2. 用 Excel 打开，保留 8 个表头。一篇文献一行；同一疾病的多篇文献写多行，每行使用不同的记录编号。
3. 保存类型选 **CSV UTF-8（逗号分隔）**。本功能接受 `.csv`，不直接接受 `.xlsx`、PDF 或文献链接文件。
4. 网页上点击“导入／导出资料”→“选择 CSV 文件”，检查预览后“确认导入”。编号错误、分类组、重复记录编号、缺少文献来源等会报错，整批导入不会执行。
5. 搜索范围选“症状／辅助检查”，输入刚填写的关键词，确认能定位疾病。要检索亚型，勾选“包含疾病亚型”。
6. 点击“导出全部资料 CSV”备份。导入后的更改仅在当前浏览器保存，**不会自动写入 GitHub 或公开网站**。

### 表格字段

| 列名 | 怎么填 |
|---|---|
| 记录编号 | 必填，如 `ORPHA65-001`；字母、数字、短横线、下划线，不超过 80 字符。更新原记录时保持编号；新文献换新编号。不要把同一编号改到另一疾病。 |
| ORPHA编号 | 必填，如 `65`；以目录为准，不能填分类组编号。 |
| 疾病名称 | 方便人工核对，可留空自动补齐；实际关联使用 ORPHA 编号。 |
| 症状体征 | 文献明确报告的表现，可用分号分隔；阴性表现与未提及信息要明确标注，避免当作阳性表现录入。 |
| 辅助检查 | 如 OCT、眼底、ERG、影像或基因检测的具体表现及单位；未报告可留空。 |
| 鉴别诊断 | 文献提及的鉴别疾病及依据，可留空；此列暂不参与症状／检查检索。 |
| 参考文献 | 标题、作者、年份、PMID／DOI 等；每条临床记录至少提供此列或文献链接。 |
| 文献链接 | 单个完整的 `https://...` 或 `http://...` 地址；可留空，但需提供参考文献。多篇来源分行记录。 |

病例中报告的表现不能直接等同于该病的典型表现；表中应保留描述范围。数据导入不会自动从论文提取内容。模板预填行仅用于填写，空白模板行不能作为有效资料导入。

### 把更新同步到网站

**方式 A：连接 GitHub 的 Cloudflare 项目（推荐）**

网页导出“全部资料 CSV”，文件名保持 `clinical.csv`，在 GitHub 进入 `data` 文件夹，上传并替换 `data/clinical.csv`，提交到 `main`。Cloudflare 自动执行 `npm run build`，校验资料并重新发布。不要把临床 CSV 放在仓库根目录。若校验失败，查看构建日志中的行号，修正 CSV 后再次提交；错误内容不会成为新版本。根目录已提交的 `index.html` 是交付快照，更新 CSV 后以 Cloudflare 构建结果或本地重新构建结果为准。

**方式 B：Cloudflare Direct Upload 项目**

网页点击“导出发布网页 index.html”，将下载文件放入原发布文件夹，替换其中的 `index.html`，保留 `_headers`、`_redirects`，再上传文件夹或 ZIP 为新部署。无需改代码。

**不要混用**：Git 自动构建会从 `src/` 和 `data/clinical.csv` 重新生成网页，因此仅替换根目录 index.html 不能更新这种部署。多人各自编辑后，先在一个浏览器依次导入大家的 CSV、解决记录编号冲突，再导出完整 CSV。不同疾病/成员建议使用不同的记录编号前缀。

### 保存与回退

- 导入先预览，确认后按记录编号合并；未出现在本次导入中的旧记录继续保留。
- 详情中的“移除记录”只修改本地；删除后同样需要导出、重新发布。
- “清除本地草稿”恢复当前网页内置资料，请先导出备份。
- 浏览器清理缓存或换设备不会自动带走草稿。新网站版本遇到旧草稿不会自动覆盖；可下载旧草稿 CSV，核对后重新导入。
- 单次导入上限 5 MB、10,000 行，单个字段上限 20,000 字符。Excel 导出中的公式前缀会转义，避免作为公式执行。

## 定义覆盖与来源

- 分类：Orphadata 眼科分类 `en_product3_189.xml`，2026-06-23。
- 定义：Orphanet Nomenclature Pack 2026，文件 `ORPHAnomenclature_en_2026.xml`，提取日期 2026-06-23，下载日期 2026-10-25；按 ORPHA 编号匹配，保留英文原文，仅移除排版标签。
- **961 个条目有定义，378 个没有独立定义**：156 个分类组，176 个亚型，46 个其他疾病实体。缺失清单见 `data/definition-coverage.json`，页面明确显示缺失状态，未编造定义，也未把上级定义充作亚型定义。Orphanet 网页直接访问在本次环境返回 403，因此未声称补齐网页可能提供的后续内容。
- 中文名：1,174 条匹配 Orphadata 中文 2020-06-01 版本；165 条为 AI 辅助工作译名。旧版中文及补充译名尚待专业核对。少量分类显示名和检索别名经过本地整理。
- 临床资料：初始为空，后续由使用者按文献整理；不包含虚构病例或测试文献。

数据来源、许可和更改说明见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。

## 项目结构与开发

```text
src/                       页面模板、样式、交互与 CSV 校验
data/catalog.json          分类、中英病名及带来源的定义
data/clinical.csv          公开临床资料的唯一构建来源
data/definition-coverage.json  定义覆盖及缺失清单
scripts/build.mjs          零依赖构建，生成 index.html 和 dist/
scripts/import-definitions.py 官方定义 XML 更新工具
tests/clinical.test.cjs     CSV 校验、合并及目录完整性测试
templates/                 空白填写模板与疾病编号对照
index.html                 可直接离线打开的交付快照
_headers / _redirects      Cloudflare 配置
```

需要 Node.js 20+：

```sh
npm test
npm run build
```

所有运行数据内嵌于生成的 HTML；浏览和搜索不发送网络请求。原始定义用英文显示，未机器翻译为中文。检索结果是资料导航，不是经过验证的鉴别诊断评分系统。
